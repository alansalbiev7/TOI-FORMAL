# Внесение изменений

Каждый PR должен указывать раздел монографии, область изменения и проверку.

1. Для формального результата укажите точную формулировку, предпосылки и символ Lean.
2. Импортируйте новый модуль через `TOI.lean`. Запустите `lake build` и оба скрипта проверки.
3. Не используйте незавершённые доказательства, аксиомы проекта или нативный
   вычислитель как недоказанное основание теоремы.
4. Для нового поведения Scala добавьте тест ошибки и предельного случая,
   выполните `bash ./gradlew test` из `asg-core`.
5. При изменении зависимостей обновите lock-файлы, обоснуйте версию и повторите проверку.
6. Не объявляйте завершёнными предусмотренные лишь архитектурой возможности.
7. Источник нормативного утверждения должен быть идентифицирован по редакции,
   статусу и области. Проект автора не является утверждённым актом.

Добавлять приложение монографии целиком следует отдельным изменением по
согласованной редакции. Название файла и номер приложения сами по себе не
задают актуальность. В PR не включаются секреты и реальные персональные данные.
