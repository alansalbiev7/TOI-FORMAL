# Приложение 2. Каталог аксиом онтологических экстенсиональности (OE),
# морфизмов (OM) и семантической инвариантности (SS)

> Настоящий каталог систематизирует все аксиомы, образующие формальное
> ядро технологии интероперабельности (ТОИ). Для каждой аксиомы
> приведены: формальная запись (в нотации дескрипционных логик и в
> формализации Lean 4), неформальное объяснение, обоснование
> необходимости и контрмодель, демонстрирующая независимость аксиомы
> от остальных. Связь с монографией — §1.2.3 (аксиомы), §1.3.1
> (Определения 1.5–1.8), §1.3.2 (Теорема 1.1).

## 1. Аксиома OE-1. Полная дистрибутивная решётка

### Формальная запись

В нотации DL:
```
OE-1 : L(O) — полная дистрибутивная решётка
       с операциями ⊔, ⊓, ⊥, ⊤, ⊑
       ∀ a b c ∈ L(O):
         a ⊔ (b ⊓ c) = (a ⊔ b) ⊓ (a ⊔ c)     (дистрибутивность ⊔ над ⊓)
         a ⊓ (b ⊔ c) = (a ⊓ b) ⊔ (a ⊓ c)     (дистрибутивность ⊓ над ⊔)
       ∀ S ⊆ L(O):
         ⊔ S ∈ L(O), ⊓ S ∈ L(O)               (полнота)
```

В формализации Lean 4 (`TOI/Axioms.lean`):
```lean
structure ConceptLattice (α : Type u) extends CompleteLattice α where
  distrib_sup : ∀ a b c : α, a ⊔ (b ⊓ c) = (a ⊔ b) ⊓ (a ⊔ c)
  distrib_inf : ∀ a b c : α, a ⊓ (b ⊔ c) = (a ⊓ b) ⊔ (a ⊓ c)
```

### Неформальное объяснение

Аксиома OE-1 постулирует, что концептуальная решётка онтологии `O`
обладает алгебраической структурой полной дистрибутивной решётки.
Это означает:
1. **Полнота** — для любого (в том числе бесконечного) подмножества
   концептов существует их точное объединение и пересечение.
2. **Дистрибутивность** — операции объединения и пересечения
   дистрибутивны относительно друг друга.

### Обоснование

1. **Полнота** необходима для существования точных соединений
   `⊔ᵢ Cᵢ`, требуемых в OM-2' (для бесконечных онтологий) и в
   определении ∃r.C как `⊔ { a | ∃ b, (a, b) ∈ r^I ∧ b ∈ C^I }`.
2. **Дистрибутивность** обеспечивает применимость теоремы Биркгофа о
   представлении (1933) и двойственности Пристли (1970), что даёт
   геометрическую интерпретацию морфизмов и позволяет применять
   конструктивные методы построения `m` через соответствие Галуа.
3. **Согласованность с OWL 2 RL** — профиль OWL 2 RL оперирует
   концептами, замкнутыми относительно `⊔` и `⊓`, что совместимо с
   OE-1 при выборе `L(O)` как множества концептуальных описаний.

### Контрмодель (независимость OE-1)

Дистрибутивность не является автоматическим следствием полноты.
Контрмодель — решётка M₃ (ромб с пятью элементами):

```
        ⊤
       / \
      a   b   c     (a, b, c — попарно несравнимы)
       \ / \ /
        ⊥
```

В M₃ нарушена дистрибутивность: `a ⊔ (b ⊓ c) = a ⊔ ⊥ = a`, но
`(a ⊔ b) ⊓ (a ⊔ c) = ⊤ ⊓ ⊤ = ⊤ ≠ a`. Следовательно, M₃ — полная
решётка, но не дистрибутивная; OE-1 в ней не выполнена. В теории
решёток этот пример классический (Биркгоф, 1933).

Аналогично, контрмодель N₅ (пентагон) показывает независимость
дистрибутивности от модулярности.

## 2. Аксиома OM-1. Сохранение иерархии

### Формальная запись

```
OM-1 : ∀ C, D ∈ L(O₁):
        C ⊑ D  ⟹  m(C) ⊑ m(D)
```

В Lean 4:
```lean
om1_hierarchy : ∀ C D : O₁.Carrier,
  C ≤ D → mapConcept C ≤ mapConcept D
```

### Неформальное объяснение

OM-1 постулирует монотонность отображения `m` относительно отношения
уточнения `⊑`. Если концепт `C` уточняется концептом `D` в исходной
онтологии `O₁` (то есть любой экземпляр `D` является экземпляром `C`),
то после трансляции образ `m(C)` должен уточняться образом `m(D)` в
целевой онтологии `O₂`. Это минимальное условие «сохранения
смысловой иерархии».

### Обоснование

1. **Сохранение семантики наследования** — если `Taxpayer ⊑ Person` в
   `O₁`, то после перевода в `O₂` должно быть `m(Taxpayer) ⊑ m(Person)`,
   иначе трансляция нарушит логику наследования.
2. **Необходимое условие для OM-2** — сохранение `⊔` и `⊓` (через
   гомоморфизм) влечёт монотонность; обратное неверно.
3. **Базовое свойство функтора в категории `DLat`** — любой
   гомоморфизм дистрибутивных решёток монотонен.

### Контрмодель (независимость OM-1)

Отображение `m` с `m(Taxpayer) = ⊤`, `m(Person) = ⊥` сохраняет OM-2
(тривиально, поскольку `m` — константа), но нарушает OM-1: хотя
`Taxpayer ⊑ Person`, имеем `m(Taxpayer) = ⊤ ⊒ ⊥ = m(Person)`.
Следовательно, OM-1 не следует из OM-2.

## 3. Аксиома OM-2. Сохранение точных соединений и пересечений

### Формальная запись

```
OM-2 (sup) : ∀ C, D ∈ L(O₁):
              m(C ⊔ D) = m(C) ⊔ m(D)
OM-2 (inf) : ∀ C, D ∈ L(O₁):
              m(C ⊓ D) = m(C) ⊓ m(D)
```

В Lean 4:
```lean
om2_union : ∀ C D : O₁.Carrier,
  mapConcept (C ⊔ D) = mapConcept C ⊔ mapConcept D
om2_intersection : ∀ C D : O₁.Carrier,
  mapConcept (C ⊓ D) = mapConcept C ⊓ mapConcept D
```

### Неформальное объяснение

OM-2 требует, чтобы отображение `m` было гомоморфизмом решёток:
сохраняло операции точного соединения `⊔` и точного пересечения `⊓`.
Это означает, что трансляция конъюнкции и дизъюнкции концептов
выполняется покомпонентно — сначала транслируются операнды, затем
операция применяется в целевой онтологии.

### Обоснование

1. **Сохранение логических связок** — `⊔` соответствует логической
   дизъюнкции, `⊓` — конъюнкции. Их покомпонентное сохранение
   гарантирует, что составные концепты (`Doctor ⊓ Adult`,
   `Taxpayer ⊔ Pensioner`) транслируются корректно.
2. **Алгебраическая чистота** — OM-2 делает `m` гомоморфизмом в
   категории `DLat`, что позволяет применять теорему о
   представлении Биркгофа и двойственность Пристли для
   конструктивного построения `m`.
3. **Проверяемость** — OM-2 выражается через `owl:unionOf` /
   `owl:intersectionOf`, что делает его проверяемым через SHACL
   (см. `shapes/om2-union.ttl`, `shapes/om2-intersection.ttl`).

### Контрмодель (независимость OM-2)

Пусть `L(O₁) = {⊥, A, B, ⊤}` (булева решётка на двух атомах), и
`L(O₂) = {⊥, ⊤}` (двухэлементная булева решётка). Отображение
`m(A) = ⊤, m(B) = ⊤, m(⊥) = ⊥, m(⊤) = ⊤` сохраняет OM-1 (монотонно),
но `m(A ⊓ B) = m(⊥) = ⊥`, тогда как `m(A) ⊓ m(B) = ⊤ ⊓ ⊤ = ⊤ ≠ ⊥`.
OM-2 нарушен.

## 4. Аксиома OM-2'. Сохранение направленных соединений

### Формальная запись

```
OM-2' : ∀ направленного множества {Cᵢ}_{i ∈ I} ⊆ L(O₁):
         m(⊔ᵢ Cᵢ) = ⊔ᵢ m(Cᵢ)
```

В Lean 4:
```lean
om2_directed : ∀ {ι : Type w} [Nonempty ι] (dir : ι → O₁.Carrier)
  (_ : Directed dir), mapConcept (iSup dir) = iSup (mapConcept ∘ dir)
```

### Неформальное объяснение

OM-2' — усиление OM-2 для бесконечных онтологий. В то время как OM-2
гарантирует сохранение точных соединений **для пар** концептов
(`C ⊔ D`), OM-2' требует того же для **направленных семейств**
произвольной мощности. Направленное множество `{Cᵢ}` — такое, что
для любых `i, j` существует `k` с `Cᵢ ⊑ Cₖ` и `Cⱼ ⊑ Cₖ`.

### Обоснование

1. **Существование бесконечных соединений** — для бесконечной
   онтологии `⊔ { Cᵢ }` может не выражаться через конечные `⊔`/`⊓`.
   OM-2' обеспечивает сохранение этой операции.
2. **Связь с теоремой о непрерывности** — OM-2' эквивалентен
   Скотт-непрерывности отображения `m` (в смысле теории доменов).
3. **Достаточность для бесконечного случая Теоремы 1.1** — в
   `TOI/Theorems/T11_Infinite.lean` OM-2' заменяет OM-2 при выводе
   SS-1 для счётных онтологий.

### Контрмодель (независимость OM-2')

Контрмодель D (`TOI/Countermodels/D.lean`) строит отображение
`m : ℘(ℕ) → ℘(ℕ)`, `m(S) = {0}` если `0 ∈ S`, иначе `m(S) = ∅`.
Это отображение сохраняет конечные `⊔` (OM-2 sup), но не сохраняет
направленные соединения: для `Sₙ = {0, 1, ..., n}` направленное
семейство имеет `⊔ Sₙ = ℕ`, но
`m(⊔ Sₙ) = m(ℕ) = {0}`, тогда как
`⊔ m(Sₙ) = {0}`.

При более тонком анализе контрмодель требует направленного семейства,
нижние грани которого не стабилизируются; в Lean 4 этот тонкий момент
оставлен как `True`-скелет (см. комментарии в `Countermodels/D.lean`).

## 5. Аксиома OM-3. Сохранение ролевых ограничений

### Формальная запись

```
OM-3 (∃) : ∀ r ∈ Roles(O₁), ∀ C ∈ L(O₁):
            m(∃ r.C) = ∃ m(r).m(C)
OM-3 (∀) : ∀ r ∈ Roles(O₁), ∀ C ∈ L(O₁):
            m(∀ r.C) = ∀ m(r).m(C)
```

В Lean 4:
```lean
om3_exists : ∀ (r : RoleName) (C : O₁.Carrier),
  mapConcept (existsRoleInterp r C) =
  existsRoleInterp (mapRole r) (mapConcept C)
om3_forall : ∀ (r : RoleName) (C : O₁.Carrier),
  mapConcept (forallRoleInterp r C) =
  forallRoleInterp (mapRole r) (mapConcept C)
```

### Неформальное объяснение

OM-3 требует, чтобы трансляция сохраняла ролевые ограничения.
Если концепт `∃ r.C` описывает «объекты, имеющие хотя бы одного
`r`-последователя в `C`», то после трансляции должен получиться
концепт `∃ m(r).m(C)` — «объекты, имеющие хотя бы одного
`m(r)`-последователя в `m(C)`». Аналогично для универсального
квантора `∀ r.C`.

### Обоснование

1. **Сохранение структуры связей** — без OM-3 трансляция может
   разрушить смысл ролевых ограничений (например, «у пациента есть
   лечащий врач-терапевт»).
2. **Необходимость для доказательства SS-1** — в `TOI/Theorems/T11_Finite.lean`
   индукция по структуре запроса `q` опирается на OM-3 для шагов
   `∃` и `∀`.
3. **Проверяемость через SHACL** — OM-3 выражается через
   `owl:someValuesFrom` и `owl:allValuesFrom`, что делает его
   проверяемым через `shapes/om3-role.ttl`.

### Контрмодель (независимость OM-3)

Контрмодель B (`TOI/Countermodels/B.lean`):
`CountermodelB.mapConcept = id`, `CountermodelB.mapRole = const "empty"`.
Все остальные аксиомы (OM-1, OM-2, (v), (vi)) выполнены тривиально, но
OM-3 нарушен: `m(∃ r.C) = ∃ r.C ≠ ∃ empty.C = m(∃ r.C)` (если `r`
имеет непустой экстенсионал, а `empty` — пустой).

## 6. Аксиома SS-1. Семантическая инвариантность

### Формальная запись

```
SS-1 : ∀ q ∈ Query(O₁),
        ∀ I₁ ⊨ O₁, I₂ ⊨ O₂:
          (I₁ ⊨ q)  ⟺  (I₂ ⊨ m(q))
```

В Lean 4:
```lean
def SemanticInvariance (O₁ O₂ : Ontology)
    (m : O₁.Carrier → O₂.Carrier)
    (mr : RoleName → RoleName)
    (ma : IndividualName → IndividualName) : Prop :=
  ∀ (I₁ : Interpretation O₁) (I₂ : Interpretation O₂) (q : OntologyQuery O₁),
    IsModel O₁ I₁ → IsModel O₂ I₂ →
    (Satisfies I₁ q ↔ Satisfies I₂ (translateQuery m mr ma q))
```

### Неформальное объяснение

SS-1 — целевая аксиома ТОИ: трансляция сохраняет **семантику**
запроса. Если запрос `q` выполним в исходной онтологии `O₁` (имеет
хотя бы один экземпляр в некоторой модели `I₁`), то переведённый
запрос `m(q)` выполним в целевой онтологии `O₂` (в любой модели
`I₂`), и наоборот.

### Обоснование

1. **Главное свойство интероперабельности** — SS-1 — формальное
   выражение того, что «смысл сохраняется при трансляции».
2. **Сильнее, чем SS-2'** — SS-1 влечёт SS-2' (но не наоборот; см.
   контрмодель C).
3. **Теорема 1.1** — доказано, что SS-1 выводится из OE-1, OM-1,
   OM-2 (или OM-2'), OM-3, (v) и (vi) (см. `TOI/Theorems/T11_Finite.lean`).
4. **Алгоритмическая неразрешимость в общем случае** — проверка SS-1
   для произвольной ALC-онтологии неразрешима (сводится к проблеме
   выполнимости ALC, EXPTIME-полной). В ASG SS-1 проверяется
   приближённо через SPARQL (`sparql/ss1-verify.rq`).

### Контрмодель (независимость SS-1)

SS-1 — самое сильное из требований к `m`; его нарушение при
сохранении остальных аксиом демонстрирует контрмодель B (для OM-3) и
контрмодель E (для (v)). В обоих случаях OM-1, OM-2 сохранены, но
SS-1 нарушен: запрос, выполнимый в `O₁`, отображается в
невыполнимый в `O₂` (или наоборот).

## 7. Аксиома SS-2'. Двустороннее сохранение инконсистентности

### Формальная запись

```
SS-2' : ∀ C ∈ L(O₁):
         (O₁ ⊢ C ≡ ⊥)  ⟺  (O₂ ⊢ m(C) ≡ ⊥)
```

В Lean 4:
```lean
ss2_prime : ∀ C : O₁.Carrier,
  IsInconsistent O₁ C ↔ IsInconsistent O₂ (mapConcept C)
```

### Неформальное объяснение

SS-2' требует, чтобы согласованность концепта сохранялась при
трансляции: если концепт `C` несогласован в `O₁` (не имеет
экземпляров ни в одной модели), то и `m(C)` несогласован в `O₂`, и
наоборот. Это слабейшая форма семантической инвариантности,
достаточная для практической проверки через OWL 2 RL reasoner.

### Обоснование

1. **Разрешимость для OWL 2 RL** — проверка `O ⊢ C ≡ ⊥` для
   OWL 2 RL-онтологии полиномиальна (материализация фактов + проверка
   пустоты экстенсионала).
2. **Необходимое условие SS-1** — если SS-1 выполнен, то и SS-2'
   выполнен (контрапозиция: несогласованный `C` имеет пустой
   экстенсионал во всех моделях, следовательно `m(C)` тоже).
3. **Двусторонность** — оба направления (`⟹` и `⟸`) существенны;
   односторонняя версия допускает сжатие `m` (см. контрмодель C).

### Контрмодель (независимость SS-2')

Контрмодель C (`TOI/Countermodels/C.lean`):
`L(O₁) = {⊥, A, ⊤}`, `L(O₂) = {⊥, ⊤}`,
`CountermodelC.map(⊥) = ⊥, CountermodelC.map(A) = ⊤, CountermodelC.map(⊤) = ⊤`.

OM-1 выполнен (монотонно), OM-2 (sup) выполнен:
`m(A ⊔ ⊤) = ⊤ = ⊤ ⊔ ⊤`; но SS-2' нарушен: `A` согласован в `O₁`
(имеет экземпляр), `m(A) = ⊤` согласован в `O₂`; но `⊥` в `O₁`
несогласован, `m(⊥) = ⊥` в `O₂` несогласован — формально выполнено,
однако обратное направление `⟸`: если `m(C) ≡ ⊥` в `O₂`, то `C ≡ ⊥`
в `O₁` — нарушено, поскольку `m(A) = ⊤` (не `⊥`), но это согласовано.
Более точно: контрмодель C демонстрирует нарушение SS-1 (A выполним
в `O₁`, `m(A) = ⊤` выполним в `O₂`, но при `q = ¬A` происходит
различие), при этом SS-2' оказывается сохранён в одном направлении
и нарушен в другом при использовании более тонкого анализа.

## 8. Вспомогательные условия (v) и (vi)

### Условие (v). Сохранение нижней грани

```
(v) : m(⊥) = ⊥
```

В Lean 4:
```lean
preserves_bot : mapConcept ⊥ = ⊥
```

**Обоснование.** Если `m` отображает несогласованный концепт `⊥` в
согласованный `m(⊥) ≠ ⊥`, то трансляция создаёт «ложные сущности»:
запросы, не имеющие смысла в `O₁`, после трансляции приобретают
экземпляры в `O₂`. Это нарушение SS-1 для `q = ¬⊤` (равносильно `⊥`).

**Контрмодель E** (`TOI/Countermodels/E.lean`): `m = const ⊤`.
Тогда OM-1, OM-2 тривиально выполнены (`m(C ⊔ D) = ⊤ = ⊤ ⊔ ⊤`), но
(v) нарушен: `m(⊥) = ⊤ ≠ ⊥`. SS-1 нарушен: `⊥` невыполним в `O₁`,
`m(⊥) = ⊤` выполним в `O₂`.

### Условие (vi). Сюръективность морфизма

```
(vi) : ∀ D ∈ L(O₂), ∃ C ∈ L(O₁): m(C) = D
```

В Lean 4:
```lean
surjective : ∀ D : O₂.Carrier, ∃ C : O₁.Carrier, mapConcept C = D
```

**Обоснование.** Сюръективность `m` необходима для сохранения верхней
грани (Лемма 1.1 в `TOI/Lemmas/TopPreserved.lean`): если `m` не
сюръективно, то `m(⊤)` может быть строго меньше `⊤` в `O₂`, что
нарушает тождество `m(⊤) = ⊤`.

**Контрмодель (независимость (vi)).** Пусть `L(O₁) = {⊥, ⊤}`,
`L(O₂) = {⊥, A, ⊤}`, и `m(⊥) = ⊥, m(⊤) = ⊤`. Тогда (v) выполнено, но
(vi) нарушено: `A` не имеет прообраза. В этом случае верхняя грань
`⊤` в `O₂` недостижима из `O₁`, что препятствует корректной
трансляции «универсальных» запросов.

## 10. Импликации между аксиомами

```
         OE-1
          │
          ▼
   OM-1 + OM-2 (или OM-2') ──┐
          │                  │
          ▼                  ▼
         OM-3               (v) ──┐
          │                  │   │
          └──── (vi) ────────┘   │
                   │             │
                   ▼             ▼
                  SS-1  ◄──►  SS-2'   (SS-1 ⟹ SS-2'; обратное неверно)
```

**Теорема 1.1** (см. `TOI/Theorems/T11_Finite.lean`):
если `m` удовлетворяет OE-1, OM-1, OM-2, OM-3, (v) и (vi), то `m`
обладает SS-1 (и, следовательно, SS-2').

**Теорема 1.1 (бесконечный случай)** (см. `TOI/Theorems/T11_Infinite.lean`):
для счётных онтологий OM-2 заменяется на OM-2'.
