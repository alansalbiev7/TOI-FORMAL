# Приложение 13. Сравнительный анализ с родственными подходами

> Настоящее приложение содержит систематический сравнительный анализ
> технологии интероперабельности (ТОИ) с пятью родственными
> подходами: (1) моделью Euzenat–Shvaiko онтологического
> сопоставления; (2) p-морфизмом ван Бентема; (3) двойственностью
> Герхке–Джонсона для дистрибутивных решёток; (4) подходом OWL
> ontology matching (Semantic Web-стек); (5) общим Semantic Web Stack.
> Сравнение проводится по 8 измерениям. Связь с монографией — §5.4.

## 2. Подробное сравнение по измерениям

### 2.1. Измерение 1. Формальное основание

**ТОИ.** Основа — концептуальная решётка онтологии как полная
дистрибутивная решётка `L(O)` (аксиома OE-1). Запросы — формулы
дескрипционной логики ALC над `L(O)`. Семантика — Tarski-интерпретации.
Это даёт стройную алгебраическую структуру с применимой теорией
двойственности.

**Euzenat–Shvaiko.** Основа — RDF-графы с эвристическими мерами
сходства (строковые, лингвистические, структурные). Нет явной
алгебраической структуры; фокус — на инженерии matchers и оценке
качества.

**p-морфизм ван Бентема.** Основа — фреймы Крипке `F = (W, R)` с
отношением доступности `R`. Модальные формулы выполняются на
состояниях `W`. Структура — теория множеств с отношениями.

**Герхке–Джонсон.** Основа — дистрибутивные решётки с топологией
(топологические пространства Пристли). Категорная двойственность.

**OWL Matching.** Основа — RDF-графы и OWL-аксиомы. Сопоставление
через `owl:equivalentClass`, `owl:equivalentProperty`,
`rdfs:subClassOf`. Нет явной алгебраической структуры за пределами
стандартного RDF.

**Semantic Web Stack.** Стек стандартов W3C: Unicode + IRIs → XML
→ RDF + RDFS → OWL → SPARQL → SHACL. Формальное основание —
дескрипционные логики + RDF-модель.

### 2.2. Измерение 2. Тип решётки

**ТОИ.** Полная дистрибутивная решётка `L(O)`. Дистрибутивность
гарантирует применимость теоремы Биркгофа о представлении (1933) и
двойственности Пристли (1970).

**Euzenat–Shvaiko.** Решёточной структуры нет. Графы сопоставляются
как множества триплетов.

**p-морфизм.** Для классической модальной логики K — булева алгебра
подмножеств `℘(W)` состояний мира. Для S4 — топологические
пространства (по Стоуну, 1937).

**Герхке–Джонсон.** Полная дистрибутивная решётка (аналогично ТОИ, но
без DL-расширения).

**OWL Matching, Semantic Web Stack.** Решёточной структуры нет.

### 2.3. Измерение 3. Семантическая инвариантность

**ТОИ.** Аксиоматически определяется через SS-1: `O₁ ⊨ q ⟺ O₂ ⊨ m(q)`
для любого запроса `q`. Доказывается в Теореме 1.1 из OE-1, OM-1,
OM-2, OM-3, (v), (vi). Приближённо проверяется через SPARQL
(`sparql/ss1-verify.rq`).

**Euzenat–Shvaiko.** Семантическая инвариантность не формализуется.
Качество сопоставления оценивается через precision, recall, F1
относительно эталонного сопоставления (reference alignment).

**p-морфизм.** Сохранение выполнимости модальных формул: если
`f : F₁ → F₂` — p-морфизм, то `F₁, w ⊨ φ ⟺ F₂, f(w) ⊨ φ`. Это
прямая аналогия SS-1, но в другой синтаксической традиции.

**Герхке–Джонсон.** Семантическая инвариантность через
Stone-непрерывность: непрерывное отображение пространств Пристли
сохраняет порядок и топологию.

**OWL Matching.** Формальной семантической инвариантности нет;
`owl:equivalentClass` сохраняет только экстенсионал (instances), а
не смысл во всех моделях.

**Semantic Web Stack.** OWL reasoner'ы проверяют консистентность, но
не инвариантность трансляции запросов.

### 2.4. Измерение 4. Автоматизация

**ТОИ.** Четырёхуровневая автоматизация:
1. SHACL-валидация (структурные ограничения OM-1/2/3).
2. OWL 2 RL reasoner (консистентность).
3. SPARQL-запросы (приближённая SS-1, SS-2').
4. Lean 4 (универсальное доказательство Теоремы 1.1).

**Euzenat–Shvaiko.** Инструментально реализованы matchers:
StringEquiv, WordNet-based, structural similarity. Тестируются на
OAEI-бенчмарках (каждый год). Автоматизации нет.

**p-морфизм.** Построение p-морфизмов обычно выполняется вручную
математиком. Алгоритмов автоматического поиска p-морфизмов мало.

**Герхке–Джонсон.** Аналогично: построение Stone-непрерывных
отображений вручную.

**OWL Matching.** Системы AgreementMaker, LogMap, COMA++ —
автоматический поиск соответствий, но без формальной верификации.

**Semantic Web Stack.** OWL reasoner'ы (HermiT, Pellet, ELK,
TrOWL) — автоматический вывод, но не проверка соответствий.

### 2.5. Измерение 5. Нормативная база

**ТОИ.** Полная нормативная база:
- Законодательная: ФЗ-149, ФЗ-152, ФЗ-210, проект ФЗ (см. Прил. 5).
- Подзаконная: проект ПП РФ (Прил. 6).
- Стандартизационная: ГОСТ Р 55062-2021, проекты ГОСТ Р «Автономные
  системы» и «ИИ-системы» (Прил. 7, 8).
- Методологическая: ТЭМ-2021 — трёхуровневая эталонная модель
  интероперабельности.

**Euzenat–Shvaiko.** Нормативной базы нет.

**p-морфизм.** Нормативной базы нет (чисто теоретическая конструкция).

**Герхке–Джонсон.** Нормативной базы нет.

**OWL Matching.** W3C-стандарты RDF, OWL — де-факто международные
стандарты, но не нормативно-правовые.

**Semantic Web Stack.** W3C-рекомендации, ISO/IEC 19757 (XML).

### 2.6. Измерение 6. Категорная семантика

**ТОИ.** В Теореме 2.1 доказывается, что категория `TOI-Cat`
онтологий и морфизмов является декартово замкнутой (CCC) — то есть
имеет терминальный объект, произведения и экспоненциал. Это даёт
семантическое основание для λ-исчисления на онтологиях и для
сопоставления функций высшего порядка.

**Euzenat–Shvaiko.** Категорной семантики нет.

**p-морфизм.** Категория Kripke-frames с p-морфизмами — это
категория, но без CCC-структуры (как показал контрпример
Фунамы–Накаямы 1949).

**Герхке–Джонсон.** Двойственность Stone–Priestley устанавливает
контравариантную эквивалентность между `DLat` и `Pries`. Это сильный
категорный результат, но не CCC.

**OWL Matching.** Категорной семантики нет.

**Semantic Web Stack.** Категорной семантики в стандартах нет, хотя
есть академические исследования по sheaf semantics и topos theory
для RDF.

### 2.7. Измерение 7. Индустриальная применимость

**ТОИ.** Реализована в пилотной зоне ASG/АСШ:
- 3 предметные онтологии (налоги, здравоохранение, регистрация).
- Кросс-доменная онтология отображений.
- Production-ready: REST/gRPC API, Redis cache, Postgres PROV-O,
  Prometheus/Grafana observability.
- 1000 RPS baseline, 10000 RPS peak, p95 ≤ 500 ms.

**Euzenat–Shvaiko.** Встроено в коммерческие продукты (TopBraid,
AllegroGraph) и в open-source инструменты (COMA++, LogMap).

**p-морфизм.** Теоретическая конструкция, не имеет индустриальных
внедрений.

**Герхке–Джонсон.** Аналогично теоретическая.

**OWL Matching.** Широко применяется в индустрии: IBM, Oracle,
SAP, TopQuadrant.

**Semantic Web Stack.** Industry standard: Google Knowledge Graph,
DBpedia, Wikidata, schema.org.

### 2.8. Измерение 8. Уровень зрелости (TRL)

**ТОИ.** TRL-6 (пилот) — 3 онтологии, pilot deployment в СМЭВ.
Цель Sprint 3 (Q2 2027) — TRL-7 (опытная эксплуатация), 10 онтологий.

**Euzenat–Shvaiko.** TRL-9 — встроено в системы TopBraid, AllegroGraph.

**p-морфизм.** TRL-2 — формальное исследование, не реализовано в
продукте.

**Герхке–Джонсон.** TRL-2 — теоретическая двойственность.

**OWL Matching.** TRL-9 — в коммерческих продуктах.

**Semantic Web Stack.** TRL-9 — международный стандарт.

## 3. Ключевые отличия ТОИ

### 3.1. Отличие 1. Аксиоматизация семантической инвариантности

В ТОИ семантическая инвариантность SS-1 — первичная аксиома, из
которой выводятся остальные требования к морфизму. В подходе
Euzenat–Shvaiko «семантическая корректность» — неявное желательное
свойство, оцениваемое post hoc через precision/recall на эталонных
данных. Это фундаментальное различие в методологии: ТОИ идёт «от
аксиом к реализации», Euzenat–Shvaiko — «от эвристик к оценке».

### 3.2. Отличие 2. Категорная структура

ТОИ вводит категорию `TOI-Cat` и доказывает её декартову замкнутость
(Теорема 2.1). Это позволяет применять λ-исчисление и теорию
доменов Скотта к онтологическим морфизмам. Ни одна из родственных
подходов не обладает CCC-структурой.

### 3.3. Отличие 3. Нормативное закрепление

ТОИ сопровождается нормативной базой (ТЭМ-2021, проекты ФЗ, ПП РФ,
ГОСТ Р) — это уникальная особенность, отсутствующая у Euzenat–Shvaiko,
p-морфизма, Герхке–Джонсона, OWL Matching. Semantic Web Stack
опирается на W3C-стандарты, но не имеет нормативно-правового
закрепления в национальном законодательстве.

### 3.4. Отличие 4. Трёхуровневая верификация

ТОИ применяет уникальную трёхуровневую верификацию: (1) SHACL для
структурных ограничений, (2) OWL 2 RL для консистентности, (3) Lean 4
для универсального доказательства. Ни один из родственных подходов не
использует совместно эти три технологии.

### 3.5. Отличие 5. Связь с формальной верификацией Lean 4

В ТОИ формальная верификация на Lean 4 + Mathlib4 является
полноценным компонентом (Теорема 1.1 формализована в
`TOI/Theorems/T11_Finite.lean`). Это сближает ТОИ с современным
направлением формальной верификации в Computer Science (Lean 4,
Coq, Isabelle/HOL), но уникально для области онтологического
инжиниринга.

## 5. Возможные синтезы

### 5.1. Синтез ТОИ + Euzenat–Shvaiko

Возможен гибридный подход:
- Использовать эвристические matchers Euzenat–Shvaiko для построения
  начального кандидата `m`.
- Применять SHACL-валидацию ТОИ для проверки аксиом OM-1/2/3.
- При нарушениях — корректировать `m` вручную или через Learner.

Этот подход реализован в ASG: `MatcherAgent` (BM25 + BERT, эвристики)
инициирует соответствия, а `ValidatorAgent` (SHACL + OWL2RL + SPARQL)
верифицирует их.

### 5.2. Синтез ТОИ + Lean 4 + Mathlib4

Lean 4 + Mathlib4 — единственный из сравниваемых инструментов,
позволяющий формально доказать SS-1 для всех `m` и `q` (а не
только для конкретных экземпляров). Это даёт математическую
гарантию, недоступную эвристическим подходам.

### 5.3. Синтез ТОИ + ГОСТ Р 55062-2021 + ТЭМ-2021

Нормативное закрепление через ГОСТ Р и проект ФЗ делает ТОИ
применимой в государственных ИС РФ. Это уникальное преимущество
перед зарубежными подходами, не имеющими правовой базы в РФ.

## 7. Применимость в государственных ИС РФ

Для государственных информационных систем РФ ТОИ обладает тремя
преимуществами перед зарубежными подходами:

1. **Нормативная совместимость** — ТОИ опирается на действующие ФЗ
   (149, 152, 210), ГОСТ Р 55062-2021 и проект ГОСТ Р «Автономные
   системы», что обеспечивает правовую определённость.
2. **Локализация стандарта** — ТЭМ-2021 — российская эталонная
   модель, соответствующая специфике межведомственного
   взаимодействия в РФ (СМЭВ, ЕГИСЗ, ФНС).
3. **Технологический суверенитет** — Lean 4, Scala 3, Apache Jena —
   open-source инструменты с открытым исходным кодом, не
   подпадающие под экспортные ограничения. Лицензия Apache 2.0
   совместима с политикой импортозамещения.

## 8. Ограничения ТОИ

Честное перечисление ограничений ТОИ:

1. **Сложность освоения** — требует знания теории решёток,
   дескрипционных логик, SHACL, Lean 4. Барьер входа выше, чем у
   OWL Matching-инструментов.
2. **TRL-6** — пока не достигнут уровень промышленной эксплуатации
   (TRL-9). Требуется апробация на 10+ онтологиях в production.
3. **Алгоритмическая неразрешимость SS-1** — в общем случае проверка
   семантической инвариантности EXPTIME-полна; на практике
   ограничена профилем OWL 2 RL.
4. **Ограниченная применимость вне государственных ИС** — для
   коммерческих применений (например, e-commerce) нормативная база
   может быть избыточной.
5. **Зависимость от Mathlib4** — формализация в Lean 4 требует
   актуальной версии Mathlib4; обновления библиотеки могут
   потребовать обновления доказательств.

## 9. Заключение

ТОИ — академический подход, обладающий уникальным сочетанием
формального основания (теория дистрибутивных решёток + DL),
категорной семантики (декартово замкнутая категория `TOI-Cat`),
нормативной базы (ТЭМ-2021, ФЗ, ГОСТ Р) и трёхуровневой верификации
(SHACL + OWL 2 RL + Lean 4). По формальным измерениям (1–3, 5, 6)
ТОИ превосходит родственные подходы; по индустриальным (7, 8) —
уступает. Дорожная карта Sprint 3 нацелена на сокращение этого
разрыва через расширение числа онтологий и промышленную апробацию.
